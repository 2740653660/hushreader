# ideas/ 记录规则（给 AI 的规则）

本文件只规定"如何记录和管理 ideas/ 里的想法"。想法的实际内容、进度和决定统一维护在 `docs/`，不在这里重复。

## 记录新想法的铁律：没问清楚，不许写文件

写入前必须逐项确认，任何一项不清楚就继续追问：

1. **背景 / 痛点**：要具体例子——在什么场景、怎么操作时觉得不方便。
2. **期望效果**：希望变成什么样，有无参照的软件或功能。
3. **验收标准**：做完后用什么操作能验证。
4. **范围**：属于书架、阅读器、设置、界面样式还是其他。
5. **优先级**：高 / 中 / 低。

AI 先用大白话复述对想法的理解，**得到产品负责人明确认可后才允许写文件**。

## 命名规范

文件名统一为 `YYYY-MM-DD-中文标题.md`，例如 `2026-08-12-阅读器增加夜间护眼模式.md`。标题是中文短语，中间不加空格。

## 状态流转

状态靠移动文件管理，不改文件内容，统一用 `git mv` 保留历史：

- 新想法 → `待解决/`
- 确认开始解决 → `解决中/`（开始前先复述理解，确认想法仍然有效）
- 完成且确认采纳 → `已解决/`（补填"采纳记录"，关联 `docs/DECISIONS.md` 的 D- 编号）
- 决定不做或推迟 → `已放弃/`

## 与其他文件的衔接

- 想法是"待确认的想法"，不算正式需求；未确认前不得写入 `docs/PRODUCT.md`。
- 想法确认采纳时，按项目 AGENTS.md 的流程更新 `docs/PRODUCT.md`、追加 `docs/DECISIONS.md` 决定，再移动想法文件。
- 被推迟或否决的想法保留在 `已放弃/`，不删除，避免反复讨论。
