# ideas/ —— 个人想法区

这里存放产品负责人提出的想法，相当于本地提交的 PR：随项目 git 一起管理，但独立于正式文档（`docs/`）之外。想法确认采纳后才会进入正式文档。

## 怎么使用

- **有新想法**：直接说"我想……"。AI 会先问清楚（背景、期望效果、验收标准、优先级），用大白话复述确认后，按 `需求模板.md` 在 `待解决/` 下新建文件。
- **想解决某条想法**：说"解决 `待解决/` 里的 XXX"。AI 按 `AGENTS.md` 里的规则走完整流程。
- **查状态**：看想法文件在哪个状态目录。

## 状态流转

想法状态靠移动文件管理，不改文件内容：

```
待解决/  ──开始做──▶  解决中/  ──完成并采纳──▶  已解决/
   │                        │
   └───────决定不做─────────┴───────▶  已放弃/
```

- 新想法 → `待解决/`
- 开始做 → `解决中/`
- 做完且确认采纳 → `已解决/`
- 决定不做或推迟 → `已放弃/`（保留记录，避免以后反复讨论）

移动文件统一用 `git mv`，保留修改历史。

## 与正式文档（docs/）的衔接

- 想法在 `ideas/` 里只是"待确认的想法"，**不算正式需求**。
- 想法确认要做时，走现有流程：更新 `docs/PRODUCT.md`，并在 `docs/DECISIONS.md` 追加一条 D- 编号决定，然后把想法文件移到 `已解决/`，在"采纳记录"里填对应的 D- 编号。
- 决定不做的想法保留在 `已放弃/`，不删除。
- 记录想法的规则见 `AGENTS.md`，单条想法的模板见 `需求模板.md`。
