# 隐阅盒第一版实施方案

状态：待产品负责人批准  
最后更新：2026-08-11

本方案说明第一版软件怎么做、做出来是什么样、分几步完成，以及完成时怎么算合格。批准后按本方案开始开发。

## 一、做出来是什么样

用户下载并安装一个 Windows 程序，打开后看到书架。可以：

1. 在“找书”页输入书名或作者，软件列出多个书源的结果供选择。
2. 选择结果和 EPUB/TXT 格式，软件显示下载进度，完成后自动加入书架。
3. 点击书籍在悬浮小窗中阅读：窗口可置顶、拖动、缩放，可调透明度。
4. 按 F12（老板键）立即隐藏/显示阅读窗；用键盘左右方向键翻页；鼠标滚轮也可翻页。这些按键都可以在设置里改。
5. 关闭主窗口时缩到系统托盘，需要时从托盘菜单真正退出；可设置开机启动。
6. 小说有更新时，手动检查并合并新章节，进度、书签、分类都保留。
7. 从软件内检查并安装新版本，不强制更新。
8. 原书源失效时，软件提示用户换一个书源并重新匹配章节。

所有数据只保存在本机，不上传任何东西。

## 二、软件由什么组成（用户不需要关心，这里只作说明）

- **外壳（Tauri）**：负责窗口、托盘、快捷键、悬浮阅读显示。Tauri 使用 Windows 自带的浏览器内核，安装包小、内存占用低。现有书架界面代码直接复用。
- **下载后台（So Novel）**：负责搜索书源和下载小说。以隐藏的本地后台进程运行，随软件启动和关闭，不需要用户安装 Java（运行时随安装包一起装）。
- **通信方式**：外壳和后台之间只在本机内部通信，不开放给外部，后台不上报任何设备信息。

> 技术保障：Tauri 已获产品负责人认可（D-022）。步骤 1 专门验证透明悬浮窗、置顶、全局快捷键和托盘四项核心能力，验证不过则切回 Electron（界面代码通用，切换成本低）。

## 三、数据放在哪里

- 软件设置、书架索引、书签、日志：`C:\Users\<用户名>\AppData\Roaming\HushReader`
- 书籍文件：默认放在该目录下的“书库”子文件夹，可在设置中修改位置。
- 旧版 HushReader（ZTools 插件版）的书架数据：首次启动时提供一次性迁移导入，导入后可继续使用；迁移失败不影响新书库。

## 四、开发步骤（对应路线图阶段）

| 步骤 | 内容 | 完成标志 |
|---|---|---|
| 1. 架构与核心能力验证 | 搭好 Tauri 外壳骨架，验证透明悬浮窗、置顶、全局快捷键、托盘在真实 Windows 上稳定；验证后台能启动、通信、退出；确定数据目录 | 打包后的 Windows 原型能打开书架，核心隐蔽阅读能力验证通过；验证不过则切 Electron |
| 2. 独立书架与本地阅读 | 替换掉 ZTools 依赖，完整实现书架、本地导入（EPUB/TXT/MOBI）、进度书签、托盘和开机启动 | 不依赖下载后台也能管理和阅读本地书籍 |
| 3. 搜索与下载 | 找书页面、多书源结果、EPUB/TXT 选择、下载进度和失败重试、自动加入书架 | 普通用户无需外部配置就能完成搜索、下载、打开阅读 |
| 4. 完整隐蔽阅读 | 悬浮窗置顶、拖动缩放、透明度、三种鼠标移出模式、老板键、全局翻页、滚轮翻页、进度可靠恢复 | 悬浮阅读在重启、休眠、显示器变化后仍稳定 |
| 5. 小说与书源更新 | 检查更新、合并新章节、书源规则更新与备份恢复、书源失效的手动切换 | 连载小说和书源规则可以安全更新 |
| 6. 发布 | 应用内更新、安装卸载流程、许可证与免责声明、GitHub 发布、干净 Windows 环境测试 | 第一版可从 GitHub 下载并安全更新 |

每一步完成后都会向产品负责人演示并确认，再进入下一步。

## 五、完成标准（第一版整体合格线）

- 从安装到完成“找书 → 下载 → 加入书架 → 悬浮阅读”全流程，无需任何外部配置。
- 加载、空书架、下载失败、书源失效、更新失败等场景都有明确提示，不会卡死或损坏已有书籍。
- 软件在真实 Windows 环境（干净的 Win10/Win11）安装、升级、卸载通过。
- 阅读数据在重启后准确恢复。

## 六、已知限制（第一版接受）

- 安装时会看到 Windows“未知发布者”警告（未购买代码签名），选择“仍要运行”即可；为减少误报风险会尽量用免费渠道提升信誉。
- 即使采用轻量的 Tauri 外壳，捆绑 Java 下载后台后安装包仍有一定体积，第一版后继续优化。
- 书架备份/导出、自动换书源、macOS/Linux 不在第一版。
